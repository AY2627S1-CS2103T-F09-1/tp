# CS2103/T Constraints

Follow the current course constraints at https://nus-cs2103-ay2627-s1.github.io/website/admin/tp-constraints.html.

* Evolve the supplied codebase in small working increments.
* Optimize for one fast-typing user, with CLI access for regular tasks.
* Do not support multiple users, shared computers, or regular access to another user's data file.
* Store data locally in a human-editable text file with at least AB3's editing support.
* Read and write only in the folder containing the JAR and its subfolders; do not change OS settings.
* Do not use a DBMS. Use object-oriented design as the primary paradigm.
* Support Windows, Linux, and macOS; avoid OS-specific APIs and behavior.
* Require only Java 25 and no installer. Do not depend on a team-operated remote server.
* Use third-party software only when it is free, open source where applicable, permissively licensed, needs no user installation, complies with every constraint, and has teaching-team approval. Avoid services that require user accounts.
* Keep the GUI effective at 1920x1080 at 100% and 125% scaling, and usable at 1280x720 at 150% scaling.
* Package the product as one JAR, or one ZIP if a JAR alone is impossible. Keep the product artifact at or below 100 MB and avoid unnecessary assets and dependencies.
* Provide a fallback for any public network API and obtain NUS IT approval before using NUS data.
* Avoid features that are hard for peer testers to exercise. Keep input primarily command based, provide a CLI alternative for mouse actions, favor normal typing over key combinations, and offer a one-shot form alongside any multi-step expert workflow.
* Keep the product's target use realistic for a small standalone desktop application. Seek course clarification before proceeding when compliance is uncertain.
